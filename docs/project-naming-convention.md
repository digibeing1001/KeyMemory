# 项目命名规范

本规范定义 KeyMemory 中"项目"（Project）的命名规则，目标是让项目名称既符合人类阅读习惯，又方便智能体（Agent）解析和检索。

## 为什么需要规范

项目是 KeyMemory 组织记忆的核心维度。一个清晰的项目名称能：

- **人类侧**：让用户在项目树、搜索结果、整理建议中快速定位
- **Agent 侧**：让智能体在检索记忆、写入上下文、生成接龙日志时准确匹配
- **跨会话侧**：让新会话能从记忆库中恢复项目上下文，实现接力工作

模糊的项目名（如"工作"、"杂项"、"temp"）会让记忆检索失准，智能体无法建立有效关联。

## 命名原则

### 1. 具体优先于通用

项目名应指向一个具体的对象、产品、任务或领域，而非一个类别、状态或动作。

| 好 | 坏 | 原因 |
|---|---|---|
| KeyMemory | 项目 | "项目"是类别，不是具体对象 |
| 订单中台 | 工作 | "工作"过于宽泛 |
| Q3 财报分析 | 文档 | "文档"是类型，不是项目 |
| 用户画像系统 | 开发 | "开发"是动作，不是对象 |
| 博客迁移计划 | 临时 | "临时"是状态，会随时间失效 |

### 2. 稳定优先于临时

项目名应能在较长时间内保持有效，避免使用会过期的信息。

| 好 | 坏 | 原因 |
|---|---|---|
| 个人博客 | 2024年博客 | 年份会过期 |
| 读书笔记 | 本月阅读 | "本月"会失效 |
| 简历系统 | v2 重构 | 版本号会迭代 |

### 3. 可读优先于可编码

项目名是给人看的，不是给编译器看的。使用自然语言而非编程标识符。

| 好 | 坏 | 原因 |
|---|---|---|
| 订单中台 | order_platform | 下划线编程风格 |
| 用户画像 | UserProfile | 驼峰编程风格 |
| Q3 财报 | q3finance | 无分隔，难读 |

## 字符规范

### 允许的字符

- **中文**：汉字、中文标点（顿号、书名号等）
- **英文**：大小写字母、数字、连字符（`-`）、空格
- **符号**：点（`.`）、括号（`()`）、冒号（`:`）用于版本或子项标注
- **其他**：Unicode 文字（日文、韩文等）

### 禁止的字符

- **路径分隔符**：`/`、`\`（会与项目路径冲突）
- **控制字符**：换行、制表符等
- **特殊符号**：`<`、`>`、`|`、`*`、`?`、`"`（文件系统不兼容）
- **编程前缀**：不以 `.`、`-`、`_` 开头

### 长度规范

- **最短**：中文 ≥ 2 字，英文 ≥ 4 字符
- **最长**：≤ 64 字符（超出会被截断显示）
- **推荐**：4-20 字符，足够具体又不冗长

## 层级规范

项目支持父子层级（通过 `parentId` 建立）。层级路径用 `/` 分隔，存储在 `path` 字段。

### 层级深度

- **推荐**：≤ 3 层（如 `公司/产品线/KeyMemory`）
- **最大**：≤ 5 层（超过会让导航和检索变复杂）

### 层级命名

- **父项目**：使用组织、领域或产品线名（如"公司"、"个人项目"、"研究"）
- **子项目**：使用具体项目名（如"KeyMemory"、"博客系统"）
- **避免**：同一层级下出现语义重复（如"项目/KeyMemory 项目"）

### 路径示例

```
个人项目
├── KeyMemory
│   ├── 文档站点
│   └── CLI 工具
├── 博客系统
└── 读书笔记

工作
├── 订单中台
│   ├── 支付模块
│   └── 库存模块
└── 用户画像系统
```

## 语言规范

### 单语言优先

项目名应使用单一语言，不混用中英文（除非是专有名词）。

| 好 | 坏 | 原因 |
|---|---|---|
| 订单中台 | 订单Platform | 中英混用难读 |
| Order Platform | Order 中台 | 中英混用难读 |
| KeyMemory | Key 记忆 | Key 是专有名词可保留 |

### 专有名词保留

技术专有名词、产品名、品牌名保留原文，不强制翻译。

- **保留**：KeyMemory、React、TypeScript、OpenAI、GPT-4
- **翻译**：Order Platform → 订单平台（如果是中文项目）

## Agent 解析友好性

### 命名可预测性

Agent 通过项目名进行语义匹配和检索。命名应让 Agent 能：

1. **从名称推断内容**：看到"订单中台"就知道是订单相关记忆
2. **区分不同项目**：不会把"订单中台"和"订单分析"混淆
3. **建立关联**：能识别"订单中台/支付模块"是订单中台的子项目

### 避免歧义

- **不用缩写**：用"用户界面"而非"UI"（除非缩写是行业通用）
- **不用代号**：用"支付模块"而非"模块A"
- **不用编号**：用"简历系统"而非"项目001"

### 与记忆内容一致

项目名应与该项目下的记忆内容主题一致。如果记忆内容偏离项目名，说明：

- 项目名需要更新
- 记忆应该归类到其他项目
- 需要创建新项目

## 通用名黑名单

以下名称过于通用，系统会判定为"非具体项目名"，不作为整理建议的候选：

**中文**：未分类、工作、学习、笔记、临时、杂项、其他、其它、默认、全部、所有、日常、琐事、事项、内容、资料、文档、记录、想法、灵感、待办、任务

**英文**：uncategorized、unclassified、default、general、global、misc、miscellaneous、migrated、memory、memories、notes、note、temp、tmp、test、tests、testing、dev、devel、develop、development、src、source、lib、libs、bin、build、docs、doc、work、works、study、learning、learn、projects、project、stuff、things、other、others、all、inbox、draft、drafts、archive、archived

## 示例

### 个人开发者

```
个人项目
├── KeyMemory           # 记忆系统主项目
├── 个人博客            # 博客系统
├── 读书笔记            # 阅读记录
└── 简历系统            # 简历管理

学习
├── 机器学习            # ML 学习笔记
├── 英语学习            # 英语学习记录
└── 论文阅读            # 论文笔记
```

### 团队协作

```
公司项目
├── 订单中台
│   ├── 支付模块
│   ├── 库存模块
│   └── 物流模块
├── 用户中心
│   ├── 认证服务
│   └── 画像系统
└── 数据平台
    ├── 数据采集
    └── 数据分析
```

### 研究项目

```
研究
├── LLM 记忆架构        # 关于 LLM 记忆机制的研究
├── Agent 协作模式      # 多 Agent 协作研究
└── 知识图谱           # 知识图谱相关研究
```

## 验证规则

系统在创建项目时会进行以下验证：

1. **非空**：项目名不能为空
2. **长度**：中文 ≥ 2 字，英文 ≥ 4 字符
3. **字符**：不含禁止字符
4. **通用名检测**：通用名会被标记，不参与整理建议
