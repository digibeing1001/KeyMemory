# 记忆邮箱与 Agent 使用协议

记忆邮箱是 KeyMemory 汇集具体项目、任务和事件上下文的主入口。它模拟真实工作邮箱，但不连接 Gmail、Outlook 或任何外部邮件服务。

## 一事一主题

一项可以明确命名并需要持续跟进的工作，只建立一个邮件主题。背景、进展、决定、更正、问题和下一步都通过回复追加。

标题应说明“正在推进什么”或“当前需要解决什么”。`飞书`、`前端`、`项目`、`任务`等分类名不能作为主题。旧项目目录不会直接转换成邮件；目录中的记忆先回到公共记忆池，等真实工作出现后再建立自然的主题。

## 三类发件人

- 人类：补充背景，纠正信息，提出问题，确认决定和验收结果。
- Agent：写回工作进度、结果、阻碍、重要发现和下一步。
- 记忆秘书：检查关联记忆并去重，只在出现新变化时追加整理邮件。

记忆秘书不会启动或唤醒 Agent。Agent 只有在被宿主调用后，才会主动读取邮箱。

## Agent 的标准读取顺序

1. 调用 `memory_inbox_list`，按主题或关键词查找同一件事情。
2. 找到主题后调用 `memory_thread_context`，先理解当前情况、最近回复、未完成事项和关联记忆。
3. 需要核对完整往来或技术附件时，调用 `memory_thread_read`。
4. 再使用 `memory_search` 补充跨项目通用的偏好、规则、事实和经验。
5. 只有确认不存在相关主题时，才调用 `memory_thread_create`。

这套顺序防止 Agent 只读到几条零散记忆，就误以为掌握了整个项目进度。

## Agent 的标准写入顺序

工作出现有意义的变化时，调用 `memory_thread_reply` 回复原主题。适合写回的内容包括：

- 已完成的阶段和可验证结果；
- 新发现的问题、阻碍和影响；
- 已确认的决定以及决定带来的变化；
- 需要人类或其他 Agent 回答的问题；
- 下一步、负责人或验收条件；
- 对之前邮件的明确更正。

“处理中”“已完成”“没有问题”不能单独成为一封进度邮件，因为它们无法支持下一位接力者。

通用事实、偏好、规则和经验先写成原子记忆；如果它也与当前工作有关，再调用 `memory_thread_link_memory` 建立引用。同一条记忆可以支持多个邮件主题。

## 邮件写作规范

标题和正文同时服务人类与 Agent，因此必须满足：

- 使用自然、克制、完整的书面句子；
- 先写最重要的变化，再说明背景和影响；
- 区分已经确认的事实、尚待确认的问题和下一步；
- 不使用“基于上下文”“综上所述”“值得注意的是”等模板化 AI 表达；
- 不展示内部数据库编号、工具调用过程或推理草稿；
- 不把推断写成事实；
- 正文不堆代码、日志、JSON、报错堆栈、硬件输出或大段配置。

技术内容放入附件。Agent 可以通过 `attachments` 参数提交；直接出现在代码块中的内容也会被 KeyMemory 自动提取为折叠附件。人类在网页中粘贴代码块时采用同一规则。

## 记忆秘书怎样整理

调用 `memory_mailbox_sync` 时，记忆秘书会：

1. 检查当前 Agent 有权访问、但尚未进入邮件主题的工作记忆；
2. 只把置信度足够高的具体项目、任务或事件归入已有主题，或建立清楚的新主题；
3. 检查已有主题，找出上次摘要后发生变化的关联记忆；
4. 跳过已经覆盖的内容；
5. 用通俗书面语言生成摘要；
6. 将来源记忆作为折叠附件；
7. 回复到原主题。

通用知识、偏好和规则不会被机械建成邮件；低置信度内容宁可留在记忆库中。没有新变化时也不会制造重复邮件。宿主可以按约定时间调用同步，也可以由 Agent 在读取邮箱时主动调用。

## MCP 工具

### `memory_inbox_list`

列出当前 Agent 可见的收件箱。具体工作开始或恢复时优先调用。

### `memory_thread_create`

建立主题。必填：清楚的 `subject`、`project | task | event` 类型和可读正文。

### `memory_thread_context`

返回适合接力的紧凑上下文，并将邮件标记为当前 Agent 已读。

### `memory_thread_read`

返回完整邮件、折叠附件和关联记忆，用于精确核对。

### `memory_thread_reply`

回复进展、问题、决定或更正。Agent 的正文会接受人类可读性检查，技术内容自动折叠。

### `memory_thread_link_memory`

把原子记忆作为来源、依据、决定、任务、参考或更正关联到主题。

### `memory_mailbox_sync`

让记忆秘书检查一个主题或所有可见主题。不会唤醒其他 Agent。

## 权限和兼容性

邮件线程和关联记忆都遵守 `agent_space`。全局主题可以引用全局记忆；私有空间的记忆不能越权附加到其他空间。

每个邮件主题在底层保留一个隐藏范围，用于兼容旧的 Context Pack 和 Loop Harness。这个内部范围不会显示为用户项目文件夹，也不应由 Agent 当作新的项目树管理。

旧 Agent 即使只调用 `memory_context_pack`，也会先收到相关邮件线程，再收到补充的原子记忆；新 Agent 应直接使用邮箱工具以获得最清楚的行为约束。

## 接入验收

一个 Agent 只有同时通过以下检查，才算真正接入：

1. 能列出 `memory_inbox_list`、`memory_thread_context` 和 `memory_thread_reply` 等工具；
2. 能读取收件箱和一个真实主题；
3. 能用自然语言回复进展，并重新读取该回复；
4. 代码或日志没有出现在正文，而是在折叠附件中；
5. 没有为已有工作新建近似重复主题。
